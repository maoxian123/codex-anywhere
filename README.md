# Codex Anywhere

通过统一网页远程使用自己电脑上的 Codex。管理中心使用 Python + Flask；每台 Windows、macOS 或 Linux 电脑运行 Python 节点，由节点启动本机的 `codex app-server --listen stdio://`。浏览器关闭或网络暂时中断后，节点仍继续运行。

```text
手机 / 电脑浏览器
       │ HTTPS / WebSocket
Flask 管理中心 ── 数据库、图片、历史、引用快照
       │ 节点主动建立 WebSocket
Python 节点 ── stdio JSON-RPC ── 本机 Codex ── 项目与工具
```

当前应用版本为 v0.1，使用 v5 会话托管协议（包含 v4 执行设置与原生历史分页）：单管理员、单管理中心进程。节点自动发现本机 Codex 项目和最近会话，打开时读取有限的最新历史，较早正文按需加载。支持模型与推理强度选择、原生审批与沙箱设置、流式消息、图片、任务与网页引用、审批/问题交互、补充要求和中断。Codex 登录状态、项目文件和实际执行保留在节点。

新版节点支持检查会话是否被其他 Codex 占用、接管原生会话和释放托管。能确认外部 Codex 进程身份时，可在核对进程信息后结束该进程并接管；结束整个进程也可能影响其其他会话。无法确认归属或权限不足时，页面保留退出指引和重新检查入口。

会话托管状态显示在标题栏，点击状态按钮可查看占用进程、重新检查、接管或释放；详细说明按需展开，不占用聊天正文区域。

切换会话、退出网页或连续 5 分钟没有操作时，网页会请求释放托管；断网或页面异常关闭时，节点在最后一次续约后最多约 90 秒检测过期。正在执行或等待审批的任务继续运行，完成后再释放；其他标签页仍在使用时也保留托管。释放保留原生历史和审批/沙箱设置，之后可从真机 Codex 或网页继续。同一会话的 writer 功能需要支持原生锁目录与 `thread/unsubscribe` 的 Codex（已按 0.163.0 核对）。升级时需更新 Python 依赖、重启节点和管理中心，并重新构建前端。

本项目围绕 Codex 原生 Thread / Turn / Item 协议实现，不包含通用 Agent 适配层。协议约定见 [docs/protocol.md](docs/protocol.md)。

## 开发环境初始化

需要 Python 3.11+（建议 3.12）、Node.js 22.12+（建议 24）、npm 和 Git。运行节点的电脑还需安装 Codex CLI，并在同一个系统用户下完成登录。管理中心本身不需要 Codex。

仓库中的 `.venv`、`.env`、运行数据和前端依赖均已加入 Git 忽略列表。

Windows PowerShell：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\codex-anywhere.exe init
Set-Location web
npm ci
npm run build
Set-Location ..
.\.venv\Scripts\codex-anywhere.exe server --host 127.0.0.1 --port 5000
```

macOS / Linux：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/codex-anywhere init
cd web
npm ci
npm run build
cd ..
.venv/bin/codex-anywhere server --host 127.0.0.1 --port 5000
```

`init` 会创建 `.env` 并生成随机会话密钥和管理员密码；已有配置不会被无意覆盖。用生成的管理员账号登录 `http://127.0.0.1:5000`。不要提交或分享 `.env`。

本地默认使用 SQLite，首次启动自动创建表。配置项见 [.env.example](.env.example)：

| 配置 | 用途 |
| --- | --- |
| `SECRET_KEY` | Flask 会话签名密钥，需要长期保存 |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | 单管理员登录凭据 |
| `DATABASE_URL` | SQLite 或 PostgreSQL SQLAlchemy 连接串 |
| `ASSET_DIR` | 图片文件存储目录 |
| `COOKIE_SECURE` | HTTPS 部署时设为 `true` |
| `PUBLIC_URL` | 浏览器访问的完整外部 Origin，例如 `https://codex.example.com`；用于 WebSocket 来源校验 |

登录后，在左上角“设备与设置”菜单中打开“设置”，即可修改管理员用户名和密码。
修改时需输入当前密码；新密码留空则只修改用户名。保存立即生效，无需重启；当前浏览器保持登录，其他已登录会话会失效。

管理员配置保存在管理中心数据库中，密码仅保存哈希，不会返回到网页或写入 `.env`。
`ADMIN_USERNAME` 和 `ADMIN_PASSWORD` 用作初始登录凭据；在设置页面保存过账号后，数据库中的配置优先于这些环境变量，重启后仍然有效。
部署升级时先运行 `codex-anywhere db-upgrade`，再重启管理中心并构建新版前端；本地 `server` 命令会自动执行数据库迁移。

前端修改后重新运行 `npm run build`。使用 `npm run dev` 热更新开发时，将 `.env` 中的 `PUBLIC_URL` 设为实际 Vite 地址（例如 `http://localhost:5173`），重启 Flask 后从该地址访问。前后端开发、构建和检查脚本以 [web/package.json](web/package.json) 为准。

## 连接工作电脑

可以直接运行节点启动脚本，在本机网页中填写服务端地址和配对码，无需手工拼接配对命令。

Windows 双击仓库根目录的 `start-node.cmd`，或在 PowerShell 运行：

```powershell
.\start-node.ps1
```

Linux 在仓库根目录运行：

```bash
bash ./start-node.sh
```

脚本检查 Python 3.11+，自动建立或复用仓库的 `.venv` 并安装所需 Python 依赖，然后启动本地节点管理服务。首次运行需要能下载 Python 依赖；节点不需要 Node.js 或构建 Hub 前端。运行前请安装 Codex CLI，并在同一个系统用户下完成 `codex login`。

默认网页地址为 `http://127.0.0.1:5780`，脚本会尝试自动打开浏览器。在网页填写 Hub 的地址、网页生成的配对码和设备名称，点击配对后节点自动连接。高级设置可以指定 Codex 可执行文件路径，以及显式允许临时调试用的 HTTP 连接。页面显示连接状态，支持启动、停止和停止后重新配对。配对码只用于这次请求，不会保存在浏览器或本地配置中。

管理服务仅监听本机回环地址，接口检查来源及 CSRF。关闭配置网页不会停止节点；保持启动脚本的服务进程运行即可继续工作。按 Ctrl+C 退出服务时会一并停止它管理的节点和 Codex。它不会自动注册 Windows 服务或 systemd 服务。

本地状态默认保存在当前用户的 `~/.codex-anywhere`。已有手工配对的 `node.json` 可以复用；重新配对使用独立 profile，保留旧节点凭据和日志。再次启动管理服务会复用保存的配对并自动连接，不需要重复输入配对码。

脚本支持传递本地管理服务参数，例如无桌面的 Linux 可以运行：

```bash
bash ./start-node.sh --no-open --port 5780 --state-dir "$HOME/.codex-anywhere"
```

无桌面远程节点可以用 SSH 转发后从自己电脑打开网页：

```bash
ssh -L 5780:127.0.0.1:5780 your-node
```

已经安装 Python 包的环境也可以直接执行 `codex-anywhere node web --no-open`。自定义旧状态目录时传入同一个 `--state-dir`，不要删除其中的凭据或指令日志。

以下手动 CLI 配对、运行方式仍然可用。

先在工作电脑检查 Codex：

```text
codex --version
codex login
```

在管理网页创建设备配对码，然后在工作电脑运行。配对无需预先指定项目目录；网页可以浏览或选择节点系统账号有权访问的任意绝对目录。

Windows 示例：

```powershell
.\.venv\Scripts\codex-anywhere.exe node pair --server http://127.0.0.1:5000 --code YOUR_CODE --name windows-workstation --state-dir .node-state
.\.venv\Scripts\codex-anywhere.exe node run --state-dir .node-state --codex-bin codex
```

macOS / Linux 示例：

```bash
.venv/bin/codex-anywhere node pair --server https://codex.example.com --code YOUR_CODE --name mac-workstation --state-dir .node-state
.venv/bin/codex-anywhere node run --state-dir .node-state --codex-bin codex
```

配对码有过期时间且只能使用一次。节点凭据保存在 `--state-dir`，该目录也保存 SQLite 指令状态与事件发件箱，应只允许运行节点的用户读取。服务端地址使用管理中心的外部地址，不是工作电脑自身的 `localhost`。

HTTP 默认仅允许回环地址。隔离局域网中临时调试明文连接时可显式加 `--allow-insecure`；实际远程部署使用 HTTPS。节点主动连接管理中心，无需在工作电脑开放入站端口。

项目目录与图片工件均不设目录白名单，也没有额外的工件目录参数。相对图片路径按任务工作目录解析；绝对图片路径可位于该账号有权读取的任意目录。模型与推理强度默认继承本机配置；新任务默认使用 `on-request` 审批和 `workspace-write` 沙箱，恢复已有会话时保留其原生设置。网页可显式选择节点支持的运行参数。

## 项目与本机已有对话

节点连接后会立即读取最近 50 条未归档 Codex 对话的标题、目录和更新时间，自动建立项目与会话列表；之后每 60 秒检查变化，只同步变化的元数据。此过程独立于网页运行，不读取完整正文或发起模型推理。某条会话离开最近 50 条窗口后，已缓存的会话、项目和历史仍会保留。

每次连接的首次发现允许 Codex 修复其原生历史索引；后续周期扫描和项目清单扫描优先只读取原生状态索引，避免每次刷新都重新扫描历史文件。不支持该优化的旧版协议会保留原有读取方式。

支持后台项目发现的节点还会在每次连接后，分页检查普通与归档会话中的目录，逐步补齐项目列表。该流程只补充项目，不批量创建所有旧会话或下载正文；前台执行繁忙或事件积压时会让出资源。每次连接的扫描有页数和项目数上限，缓存项目不会因某次扫描未出现而被删除。

项目由“设备 + 规范化后的目录”确定，同一路径在不同设备上属于不同项目，Windows 路径按大小写不敏感处理。选择在线设备后，可以浏览其主目录、磁盘和子目录，或直接输入绝对路径。选择已有目录即可打开项目；需要新目录时显式选择创建，节点才会创建该目录。新建任务可以选择项目，直接填写工作目录也会自动归入对应项目。

左侧以项目与会话列表为主，直接打开自动出现的对话即可使用。首次打开或发现本机历史有更新时，节点默认只读取最新 50 项，单页原始内容预算为 28 MiB，并保留原消息、工具结果和顺序。完成这一页即可继续原会话，无需先下载完整历史。网页按缓存页展示消息；“加载更早消息”会在需要时继续读取原生游标页。已有且未变化的正文缓存会直接复用；运行中、等待交互或正在创建的任务不会被后台历史加载打断。

较早或已归档的对话可通过次级的本机历史入口搜索、翻页、筛选并加入列表，支持 Codex CLI、IDE、桌面/App Server 和子任务来源，也可按工作目录过滤。首次正文加载期间显示导入状态，完成后才能继续发送消息；已有正文时加载更早页不会阻塞聊天。重复打开会复用同一读取命令；读取失败或执行结果未知时会显示错误，需要用户显式手动重试，不会因页面重复刷新而不断重发。手动完整导入仍单独保留；不支持原生分页或单项超预算时会明确报错，自动读取不会悄悄退回下载完整历史。

导入只读取本机 Codex 历史，不会恢复执行或发起模型推理。用户之后发送消息时，节点恢复同一个原生会话 ID，保留其上下文。相同设备上的同一原生会话重复导入会更新同一条管理记录。导入历史中的用户图片、工具图片和本地图片链接使用同一工件通道；HTTP/HTTPS 图片链接保留为链接，不在后台自动下载。

自动发现和正文加载依赖运行节点的系统账号所使用的 Codex 配置与本地历史。自动检查覆盖最近 50 条未归档会话；正文保存读取时的快照，本机版本变化后会标记为待更新。它不接管其他客户端正在运行的进程，也不提供官方客户端运行状态的实时双向同步。

## 模型、推理强度与审批设置

运行设置读取当前节点的模型目录、项目配置和管理策略。模型与可选推理强度按节点实际返回值展示；不同设备、账号和 Codex 版本的选项可能不同，保留“继承本机配置”即可使用本机默认模型与强度。新任务的审批与沙箱采用前述安全默认值，恢复已有会话时保留原生配置。模型目录用于选择，不等同于模型调用权限或额度验证。

项目默认设置用于之后新建的任务；任务设置用于该会话下一轮执行，修改时不会打断正在运行的轮次。界面区分保存的设置与节点回传的实际生效设置，节点重启后会重新校验。导入或读取已有历史不会为了应用设置而恢复执行或发起推理。

可设置模型、推理强度、审批策略、审批执行者、沙箱和网络访问。审批策略决定何时询问；沙箱决定实际文件与网络权限。`never` 不会自动变成全盘访问，`auto_review` 使用 Codex 原生审批审查流程。管理策略禁止或节点不支持的组合会返回明确错误。补充当前轮次的要求沿用当前执行参数，新的参数在下一轮开始时应用。

## 使用聊天与引用

点击“新对话”直接输入需求，无须先起名字。默认沿用当前会话的项目，也可在输入区上方切换工作项目；发送首条消息时才创建会话，并根据正文显示简短标题，后续自动同步 Codex 的原生会话名称。仍可在侧栏手动改名，自动更新不会覆盖手动名称。模型与权限放在可展开的设置中。也可在左侧打开已有本机对话，等待正文自动加载后继续聊天。消息发送到节点上的 Codex，网页展示回答、工具执行以及需要处理的审批或问题。任务执行中可以补充要求或中断。

输入框的模型旁常驻显示 Codex 快速、正常或其他速度模式，已有会话使用实际读回值，新建页显示节点的新对话默认模式。快速模式单独强调，离线值注明缓存；节点未提供模式时明确显示“模式未知”。此标识只读，不会因调整模型或权限而改动速度设置；旧节点缺少读回能力时需更新并重启节点。

草稿按当前登录用户、会话或新建项目保存在此浏览器标签页中，切换会话、进入设置和刷新页面后仍可继续编辑；发送失败保留草稿，发送成功后清除。模型、推理强度和权限紧邻输入区显示，正在执行时修改的设置明确标为下次生效。普通邮箱和代码中的 `@` 保持原样；在空白后输入 `@` 可搜索会话引用，按 Esc 关闭候选并保留输入。

侧栏使用一个滚动列表，项目的展开、筛选和新建对话是独立操作；可切换最近、运行中、待处理和已归档视图。会话菜单支持置顶、自定义显示名、归档和恢复，这些偏好保存在管理中心并同步到其他浏览器。归档仅隐藏管理中心列表中的会话，不停止任务，也不改变原生 Codex 的归档状态；本机历史中的原生归档会话仍从“设备 → 更多本机历史”读取。设备和全局设置入口固定在侧栏底部。

连续的思考、命令和工具记录合并为默认折叠的“工作过程”，摘要显示思考与工具次数、执行状态和失败提示；展开后可继续查看每项详情和完整内容。消息正文、图片和需要处理的审批仍直接显示，跳转引用时会自动展开目标记录。

- 图片：上传有效图片，或查看 Codex 生成、读取和工具返回的图片。每张图片最多 20 MiB、2500 万像素；节点对每项工具或消息输出最多提取 16 张、合计 40 MiB，超出部分跳过并记录日志。图片通过需要登录的附件接口访问。回答中已经嵌入的图片不会在同条消息的图库重复展示；其他附件与工具图片仍保留在图库中。
- 任务引用：选择已接入的任务，可引用具体消息。中心保存引用时的快照，将引用内容作为明确的上下文交给 Codex；卡片可跳转到原任务。
- 网页引用：提供 HTTP/HTTPS URL、标题和摘录，引用卡片打开原网页。中心不会抓取任意 URL；模型可见内容来自用户提交的摘录。Codex 自己搜索时的来源展示取决于其返回的数据。

引用快照不会随着被引用任务继续对话而悄悄变化。暂不自动导入 ChatGPT Web 聊天或接管官方桌面端 / IDE 正在运行的进程。

## Docker + PostgreSQL 部署

管理中心使用 Docker Compose，节点仍运行在各工作电脑上。先在仓库生成 `.env`，设置独立的数据库密码：

```bash
.venv/bin/codex-anywhere init
# 编辑 .env：HTTPS 部署设 COOKIE_SECURE=true 和 PUBLIC_URL=https://codex.example.com。
docker compose up -d --build
docker compose logs -f hub
```

镜像使用多阶段构建打包前端，Python 服务使用非 root 用户。入口脚本先执行 `codex-anywhere db-upgrade`，再启动 Gunicorn。数据库数据和图片分别存储在命名卷 `postgres_data`、`asset_data`。

管理端口仅发布到 `127.0.0.1:5000`。将 [deploy/Caddyfile.example](deploy/Caddyfile.example) 中的域名与邮箱替换为实际值，使用宿主机 Caddy 代理此地址。代理必须支持 WebSocket 升级并保持原始 Host / Origin；Caddy 的 `reverse_proxy` 支持 WebSocket。HTTPS 上线后将 `COOKIE_SECURE=true`、`PUBLIC_URL=https://你的域名`，并用 HTTPS 地址重新登录及配对。`PUBLIC_URL` 明确指定允许的浏览器来源，应用不信任任意转发头来推断来源。

使用其他反向代理时，为 `/ws/client` 和 `/ws/node` 保留长连接，不要缓存 API 或聊天事件。不要通过任意可控请求头重写鉴权依据。

**保持 Gunicorn 单 worker，禁止 `--preload`。** 当前节点连接、浏览器订阅与指令路由位于进程内，线程数用于支持并发 WebSocket。多个 worker 或多个管理中心实例需要额外的跨进程路由，目前没有实现。

升级前备份数据库、图片卷与 `.env`。单独升级数据库时运行：

```bash
.venv/bin/codex-anywhere db-upgrade
```

`docker compose down` 保留命名卷；删除卷会删除历史和图片。数据库与图片必须一起备份才能完整恢复对话中的工件。

### 从旧版升级到 v4

管理中心、网页构建和所有节点都需要一起升级。停止旧管理中心和节点，备份数据库、图片、`.env` 与节点状态目录；更新代码并重新安装 Python 依赖、构建前端，然后执行 `codex-anywhere db-upgrade`，再启动管理中心和节点。Docker 部署重新构建镜像，入口会先运行同一迁移命令。

数据库迁移包含旧版项目归组、导入状态和稳定的历史顺序；`0004_automatic_sync` 记录同步和缓存版本，`0005` 继续添加节点能力、项目与任务执行设置、实际生效版本、原生历史游标与覆盖状态。已有完整缓存会保留完整覆盖标记。节点继续使用原状态目录，保留设备 ID、令牌与指令日志，无需重新配对；旧配置中的 `roots` 字段在加载时移除。旧版目录相关 CLI 选项已删除，启动命令使用上方示例。

升级后，节点与新管理中心连接成功即开始自动发现最近 50 条会话，正文在打开时按需分页读取。管理中心、重建后的网页和节点都需要更新：新节点只有收到管理中心 `welcome` 中的 `catalogSync` 能力确认才启动自动同步；节点通过 `lazyHistory`、`runtimeSettings` 和 `projectInventory` 分别声明原生分页、执行设置和后台项目发现能力。旧节点保留兼容流程，使用新增功能需更新并重启节点。

## 断线、重试与状态

节点将观察到的事件先写入 SQLite 发件箱，管理中心提交数据库后确认；重连后补传未确认事件，中心按事件 ID 去重。浏览器按事件游标重新订阅并读取已持久化历史。

每条指令都有幂等 ID。已完成的重复投递返回缓存结果。如果节点进程在指令发出后崩溃，无法确定结果的指令标记为 `unknown`，不会自动重复执行；用户应先检查任务实际结果，再决定是否发起新的操作。断网时也不会承诺恢复尚未被节点观察、落盘的流式片段。

Codex 进程重启会生成新的运行实例 ID，旧实例的审批不能继续提交。断开网页连接不会终止节点或 Codex；停止节点进程则会停止它管理的 Codex 子进程。

执行错误及其附加说明会保留在界面中，成功的后台列表刷新不会将错误提示清除。任务最近一次错误持久化保存，重新打开任务仍可查看；开始新的执行后按最新任务状态更新。登录会话过期时返回登录页，重新登录后可继续读取历史。

Codex 声明会自动重试的临时错误不会将任务标为失败。迟到的旧指令结果不会覆盖新轮次；多个审批同时等待时，任务会保持等待，直到所有请求处理完毕。补充要求中的原文和引用也会绑定到对应消息。

注销会同时撤销当前会话的 Cookie 和已有网页长连接。管理中心重启后需要重新登录；节点运行不依赖浏览器登录会话。缺失或越界附件会返回明确错误，可重新上传后再发送。

### 使用真实 Codex 验证

[scripts/live_smoke.py](scripts/live_smoke.py) 可重复运行真实端到端测试。它使用当前系统用户下已经安装并登录的 Codex CLI，**会发起真实推理并消耗模型额度**。脚本启动隔离的临时管理中心（默认 `http://127.0.0.1:5010`）、节点和测试工作目录，不使用日常项目；运行前确保该端口空闲。

Windows PowerShell：

```powershell
.\.venv\Scripts\python.exe scripts/live_smoke.py --hold --timeout 180
```

macOS / Linux：

```bash
.venv/bin/python scripts/live_smoke.py --hold --timeout 180
```

检查范围包括：

1. 真实模型问答与回答回传。
2. 上传图片并由模型识别。
3. 工具图片上传与回传。
4. 大于 1 MiB 的图片传输。
5. 任务引用与用户提供的网页摘录进入模型上下文。
6. 网络断线后恢复连接，并保持同一 Codex 进程 PID。
7. 运行中补充要求（steer）。
8. 中断当前执行（interrupt）。
9. Codex 原生网页搜索。

每次运行的报告保存在 `instance/live-tests/<id>/report.json`，具体结果以该次报告为准。`--hold` 会在检查后保留测试服务，便于打开网页继续检查图片、引用与历史；按 `Ctrl+C` 结束测试并停止测试进程。该脚本需手动执行，常规测试与 CI 不会自动运行它。

新增的运行设置与原生分页验收可使用 `.venv\Scripts\python.exe -m scripts.live_runtime_smoke --codex-bin codex`（POSIX 使用 `.venv/bin/python`）。它会进行三次简短推理，检查动态模型、推理强度、只读沙箱、下一轮设置生效、有限历史分页，以及重启后在未加载完整网页历史的情况下继续原会话；默认使用回环端口 5013。

已完成的 Windows / Codex 0.163.0 实测及测试边界见 [2026-10-20 验收记录](docs/verification-2026-10-20.md)。

项目与历史导入的最新检查见 [2026-10-21 验收记录](docs/verification-2026-10-21.md)。可用以下命令单独复测已有测试会话的导入、图片和原会话续聊；最后一步会发起一次真实推理：

```powershell
.\.venv\Scripts\python.exe scripts/live_smoke.py --projects-only --import-native-id EXISTING_NATIVE_THREAD_ID --port 5011
```

可选 `--expected-context 历史校验串` 验证续聊能回忆原会话上下文。请选择用于验收的会话；该步骤会向原生会话追加一轮消息。

实际验收建议：手机登录 → 选择工作电脑项目 → 上传截图并引用已有任务 → 处理审批 → 接收图片 → 关闭网页后任务继续 → 重新打开恢复历史。另需测试节点断网重连和运行中进程重启。

## 当前边界

- 单管理员、单管理中心进程；没有多租户、团队 RBAC 或多实例指令路由。
- 节点以命令行前台进程运行；系统后台服务安装、自动更新与桌面托盘不在 v0.1 范围内。
- Codex App Server 协议会随 CLI 版本变化。上线前固定并验证实际使用的版本，不自动升级 CLI。
- 支持新建任务、自动发现最近本机会话与按需加载正文；较早或归档会话通过手动历史入口添加，不保证共享官方客户端的实时运行状态。
- 默认继承本机模型与推理强度，新任务采用请求审批和工作区写入沙箱，恢复已有会话时保留原生配置；可按节点能力显式覆盖。具体沙箱能力取决于 Codex 与操作系统。
- 网页摘录由用户提供；没有任意 URL 抓取、ChatGPT 私有聊天自动同步或 Codex Cloud 任务接管。

规划中的后续工作包括跨版本协议兼容测试、系统服务安装、团队权限、工件生命周期以及多实例部署。
